A rotary encoder reads the angle of a shaft from a disk with $n$ tracks, one sensor per track. If the disk is printed in plain binary, the step from 0111 to 1000 changes all four tracks at once, and a reading taken while the shaft turns can mix old and new bits into any value at all. If the disk is printed so that each step changes one track, a reading taken in motion is off by at most one step. That list of strings is a Gray code. For four tracks one such list is 0000, 0001, 0011, 0010, 0110, 0111, 0101, 0100, 1100, 1101, 1111, 1110, 1010, 1011, 1001, 1000, and it closes into a ring, since 1000 is one bit away from 0000.

The same idea saves work in programs. A search that tests every subset of $n$ items, and keeps a sum of weights or a score, can update the score when one item enters or leaves. In a Gray code order each step costs $O(1)$ for the update, against $O(n)$ for computing the score from scratch. The chapter asks which classes of objects have such a listing, how to produce it with $O(1)$ work per step, and how to jump to the $k$-th object directly. It starts with binary strings, moves to strings over larger alphabets, and ends with the subsets of a fixed size.

## What the chapter covers

The chapter is in six groups, read in order.

1. **Gray codes and minimal change.** The [Gray code](/gray-code/) itself, the general notion of a [minimal-change ordering](/minimal-change-ordering/), and the task of [Gray code generation](/gray-code-generation/).
2. **The binary reflected Gray code.** The [binary reflected Gray code](/binary-reflected-gray-code/), built by reflection, and the [ruler sequence](/ruler-sequence/), which says which bit changes at each step.
3. **Ranks and strings.** [Gray code conversion](/gray-code-conversion/) in both directions: [binary to Gray](/binary-to-gray-conversion/) in one shift and one exclusive or, and [Gray to binary](/gray-to-binary-conversion/) by a prefix exclusive or.
4. **Cycles in the cube.** [Cyclic Gray codes](/cyclic-gray-code/), the [Hamiltonian cycle in the hypercube](/hypercube-hamiltonian-cycle/) that each of them is, and [balanced Gray codes](/balanced-gray-code/), in which all bits change about equally often.
5. **Loopless generation and larger alphabets.** [Loopless Gray code generation](/loopless-gray-code-generation/) with focus pointers, the task of [k-ary Gray code generation](/k-ary-gray-code-generation/), and the reflected [k-ary Gray code](/k-ary-gray-code/) with its loopless generator.
6. **Gray codes for combinations.** The task of [combination Gray code generation](/combination-gray-code-generation/) and three answers with stronger and stronger rules for a step: the [revolving door order](/revolving-door-ordering/), [Chase's sequence](/chase-sequence/) and the [Eades-McKay order](/eades-mckay-algorithm/).

## A first reading

For a first reading, take these eleven entries in order: the Gray code, the binary reflected Gray code, the ruler sequence, binary to Gray conversion, Gray to binary conversion, the cyclic Gray code, the Hamiltonian cycle in the hypercube, loopless Gray code generation, the k-ary Gray code, combination Gray code generation and the revolving door order. The three problem pages, minimal-change ordering, Gray code generation and Gray code conversion, are short and can be read at any time. Leave balanced Gray codes, Chase's sequence and the Eades-McKay order for a second pass. They prove that a code with an extra property exists, or build one from a recursion with three or four cases.
