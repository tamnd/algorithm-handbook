The checkers in these exercises follow the pseudocode of their entries, and addresses are byte numbers. [AddressSanitizer](/addresssanitizer/) uses granules of 8 bytes and redzones of $RZ = 16$ bytes on each side of an object, and RZ in a shadow list means a redzone value. [Baggy bounds](/baggy-bounds-checking/) uses slots of 16 bytes and a padded size $2^e$ with $e = \max(4, \lceil \log_2 n \rceil)$. When a check reports an error, assume the run goes on, so that later steps still have a verdict.

1. ◦ AddressSanitizer runs MALLOC(21) and gets a free chunk at address 0. Give the length of the chunk, the address $b$ that MALLOC returns and the shadow value of each granule of the chunk. Then give the verdict of CHECK for these accesses: 4 bytes at $b + 16$, 2 bytes at $b + 20$, 1 byte at $b + 20$, 8 bytes at $b + 8$, 1 byte at $b + 24$ and 1 byte at $b - 1$.

2. ◦ Under baggy bounds, ALLOC(40) returns $B = 128$. Give $e$, the padded block and the number of bytes lost to padding. For $k = 63, 64, 71, 72, -8, -9$, say whether ADD$(B, k)$ returns a pointer in the block, a marked pointer or a bounds error. Is a 4-byte store at $B + 40$ reported?

3. ◦ A toy machine has $2^{16}$ application bytes and a direct-map [shadow memory](/shadow-memory/) with $k = 4$ placed at $\mathit{off} = 2^{16}$. Give the shadow address of $\mathtt{0x2345}$ in hexadecimal and the size of the shadow region. On a 32-bit address space, how large is a direct map with $k = 4$, and with $k = 3$? What fraction of memory do 4-bit tags per 16-byte granule take, as in Arm's [memory tagging](/memory-tagging/), and what fraction does the AddressSanitizer shadow take?

4. ◦ [Software fault isolation](/software-fault-isolation/) runs with 16-bit words, $m = 12$ offset bits and segment identifier $g = 3$. Give the domain. For the store addresses $a = 100$, $20000$ and $16383$, give the address that address sandboxing produces and the verdict of segment matching.

5. ◦ A program runs with a [shadow stack](/shadow-stack/), empty at the start. `main` calls F with return address $r_1$; F records the depth $d = 1$ with `setjmp`; F calls G with return address $r_2$; G calls H with return address $r_3$; H calls `longjmp`, which runs RESTORE$(S, 1)$ and resumes F; F returns, and the normal stack gives $r_1$. Give $t$ after each step and the outcome of F's return. What happens at F's return if `longjmp` does not call RESTORE?

6. ◦ Run [lock-and-key checking](/lock-and-key-temporal-checking/) on: $p \leftarrow$ ALLOC(8), $q \leftarrow$ ALLOC(8), FREE$(p)$, $r \leftarrow$ ALLOC(8), LOAD$(p, 4)$, FREE$(p)$. The counter starts at 1, the free lock locations are $\ell_0, \ell_1, \ldots$ in that order, a freed lock location is reused first, and $r$ gets the block that $p$ had. Give the key and lock of $p$, $q$ and $r$ and the verdict of the last two steps. Does AddressSanitizer with a quarantine limit of 0 report the load? With 64-bit keys and $10^9$ allocations per second, how many years pass before the counter wraps?

7. ◦ Run [dangling pointer nullification](/dangling-pointer-nullification/) with heap objects $A = [100, 116)$ and $B = [200, 208)$ and a global at address 16. The program stores the pointer 204 at 104, the pointer 200 at 16 and the pointer 200 at 108, then stores the integer 5 at 108, which is not traced, and then calls FREE$(B)$. Give the in-set of $B$ just before the free and the values at 104, 108 and 16 after it. Which dangling pointer is left?

8. ◦ AddressSanitizer's quarantine has a limit of 1024 bytes and is empty when FREE$(p)$ puts a 64-byte chunk in it. Every later free also adds a 64-byte chunk. At which later free does $p$'s chunk leave the quarantine? From what moment can a stale read through $p$ go unreported?

9. • A 16-byte array starts at $p = 64$. The program computes $q = p + 20$, then $r = q - 10$, and loads one byte at $r$. Separately it computes $s = p + 30$, then $u = s - 20$, and loads one byte at $u$. Give the verdicts under [fat pointers](/fat-pointer/), [Jones-Kelly checking](/jones-kelly-bounds-checking/) and baggy bounds, step by step. Which verdicts are false alarms?

10. • Decide which of AddressSanitizer, Jones-Kelly checking and [SoftBound](/softbound/) reports each error. (a) A heap structure has `char name[12]` at offset 0 and `int id` at offset 12, and the code writes `name[12]` through a pointer to `name`. (b) Through a pointer $p$ to a 32-byte heap array, one store goes to $p + 100$, computed in a single step, which lands in the middle of another live heap object. (c) A load goes through a stale pointer after its chunk has left the quarantine and been handed out again for a new object of the same size. Name one checker of the chapter that reports (c) for certain.

11. • In AddressSanitizer the shadow of granule $[0, 8)$ is 0 and that of $[8, 16)$ is a redzone. What does CHECK do for a 4-byte load at address 6, and is the access safe? Then prove that for an access of $w \in \{1, 2, 4, 8\}$ bytes at an address that is a multiple of $w$, line L3 reports exactly when some byte of the access is not addressable.

12. • Run SoftBound with $W = 8$. $s \leftarrow$ ALLOC(24) returns 64, for a structure with `char a[8]` at offset 0, a pointer field `f` at offset 8 and `char c[8]` at offset 16. (1) $y \leftarrow$ FIELD$(s, 0, 8)$, then STORE(ADD$(y, 6)$, 4, 0). (2) $\mathit{loc} \leftarrow$ FIELD$(s, 8, 8)$, $q \leftarrow$ ALLOC(40) returns 200, then STOREPTR$(\mathit{loc}, q)$. (3) An integer store STORE$(\mathit{loc}, 8, 230)$. (4) $r \leftarrow$ LOADPTR$(\mathit{loc})$, then LOAD$(r, 8)$ and LOAD(ADD$(r, 8)$, 8). (5) $v \leftarrow$ INT-TO-PTR(230), then LOAD$(v, 1)$. Give every pointer as a triple and every verdict.

13. • A program has $m$ indirect call sites with allowed sets $T(s_i) = \{t_i, t_{i+1}\}$ for $i = 1, \ldots, m$. Run the label build of [control-flow integrity](/control-flow-integrity/). How many classes are there, what is $T^*(s_i)$, and how many (site, target) pairs does the check accept, against the $2m$ that the policy allows? Give the numbers for $m = 10$.

14. • Remove the pad byte from Jones-Kelly checking, so that an object occupies exactly $[b, b + n)$ and LOOKUP$(p)$ returns the object with the largest base $b \le p$ if $p \le b + n$. Objects $A = [0, 8)$ and $B = [8, 16)$ are adjacent, and $a = 0$ points to $A$. Run $p \leftarrow$ ADD$(a, 8)$, CHECK$(p, 1)$, $q \leftarrow$ ADD$(p, 4)$, CHECK$(q, 4)$. Then run the same steps with the pad byte, where $B$ starts at 9.

15. • Under baggy bounds a 16-byte allocation has $B = 64$ and $e = 4$. A pointer $p = 78$ is made by ADD and used for a 4-byte store. Which line catches the error? Then prove that line L15 is never needed when $w$ is a power of two with $w \le 2^e$ and $p$ is a multiple of $w$.

16. • A two-level shadow memory has $b = 32$, $c = 16$ and $k = 3$, and each primary entry is a 4-byte pointer. Give the size of the primary table and of one private chunk. A program writes values other than the default in exactly 100 distinct chunks. How much memory do the primary table and the private chunks take, against a direct map for the same address space? How many primary entries does a SETRANGE over a chunk-aligned region of 1 MiB change, and how many SET calls does the direct map need for it?

17. • A server has a 16-bit [ASLR](/address-space-layout-randomization/) offset, and each probe tests one value. Without renewal, how many probes give a success probability of at least $1/2$? With a fresh offset at each probe? Give exact integers.

18. • A binary tree node holds two child pointers and an 8-byte key, on a machine with 8-byte words. How many bytes does a node take with plain pointers and with fat pointers of four words? Under SoftBound, the node keeps its layout and the metadata table holds 16 bytes for each stored pointer; what is the total per node?

19. • Assume a random canary that the attacker cannot read, and no information leak. For each attack, say which of a [stack canary](/stack-canary/), [data execution prevention](/data-execution-prevention/) and a shadow stack stops it. (a) A linear overflow of a stack buffer writes shellcode and its address over the return address. (b) A linear overflow writes the address of a library function over the return address, as in a [return-to-libc attack](/return-to-libc-attack/). (c) A write through a stray pointer replaces the return address and the words above it with a chain for [return-oriented programming](/return-oriented-programming/), and leaves the canary alone. (d) A [data-oriented programming](/data-oriented-programming/) attack changes no code pointer.

20. ★ Prove the optimality claim of control-flow integrity: if each target carries one label $\ell(t)$, each site expects one label $e(s)$, the check accepts $(s, x)$ exactly when $\ell(x) = e(s)$, and the check accepts every allowed pair, then it accepts every pair $(s, x)$ with $x \in T^*(s)$.

21. ★ Take again $m \ge 2$ sites with $T(s_i) = \{t_i, t_{i+1}\}$. A compiler may duplicate a target function, and each copy gets its own label. What is the smallest number of extra copies that makes the check accept exactly the allowed pairs? Prove that fewer copies do not suffice.

22. ★ Prove that line L6 of baggy bounds finds the right allocation for every marked pointer: if $r \in [B - 8, B)$ or $r \in [B + 2^e, B + 2^e + 8)$ for a block $[B, B + 2^e)$ with $e \ge 4$, then the reference address it computes lies in the block. Then show that a window of 9 bytes would break this: give the marked pointer and the address that line L6 computes.

23. ★ Prove that in lock-and-key checking CHECK$(p)$ passes exactly when the allocation that $p$ came from is still live, although lock locations are reused. Then replace the counter by a $b$-bit counter that wraps and skips the value of INVALID, so that keys cycle with period $2^b - 1$. What is the smallest number of further allocations after $p$'s that can make a stale $p$ pass, and what must happen for it? Give the number for $b = 16$.

24. ★ A forking server keeps one 64-bit canary in all its children. The low byte is 0 and known, and the other 7 bytes are random. The attacker overwrites one byte at a time, trying the values of the next byte in a fixed order; a wrong value crashes the child, and a right one does not. Find the expected number of crashes, the largest possible number, and the exact probability that the canary is found with at most 892 crashes. Compare with guessing the 56 random bits as a whole with 893 attempts, and say what a fresh canary in each child does to the byte-wise attack.
