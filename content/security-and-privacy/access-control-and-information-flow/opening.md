A bank's server holds every customer's balance, and a web page shows each customer only their own. Access control decides who may read a file or call a function. It cannot say what a program does with the data once it has read it: a function allowed to read a secret may copy it into a log, or branch on it and set a public flag. Information-flow security closes that gap. It labels data with levels, such as public and secret, and asks that nothing at a secret level can be seen at a public level, whatever path the information takes.

Two kinds of flow have to be stopped. An explicit flow copies a secret, as in $l := h$. An implicit flow goes through the control flow, as in $\mathbf{if}\ h > 0\ \mathbf{then}\ l := 1\ \mathbf{else}\ l := 0$, where no assignment mentions $h$ on its right side and the public $l$ still learns a bit of it. A correct definition must catch both, and must not forbid programs that look as if they leak but do not, such as $l := h - h$.

## What the chapter covers

1. **Noninterference.** [Noninterference](/noninterference/) says that two runs that start in states with the same public values end in states with the same public values. The termination-insensitive form ignores runs that do not stop; the termination-sensitive form also forbids the secret to decide whether the program stops. With more than two levels, a lattice of levels orders them, as in Denning's model. The entry proves that noninterference is a 2-safety property: a violation is a pair of runs, so no set of single runs can define it. It is undecidable, by a reduction from the [halting problem](/halting-problem/). Security type systems are sound for it and cannot be complete.

## A first reading

Read [noninterference](/noninterference/) in full: the definition, the table of examples and non-examples, and the proof of the theorem. Then read [self-composition](/self-composition/), which turns the property of two runs into a property of one run that ordinary verification tools can check, and [taint analysis](/taint-analysis/), which tracks explicit flows only and so does not prove noninterference. The [timing attack](/timing-attack/) of Chapter 45.4 shows a leak that this definition does not model, because time is not part of the final state.
