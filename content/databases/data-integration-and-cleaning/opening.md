A hospital group buys two clinics. One clinic stores patients in a table `Patient(name, born, phone)`, the other in `Client(fullname, dob, tel, ward)`, and the group wants one list of patients and one query that runs over both. First someone must see that `name` and `fullname` mean the same thing. Then the correspondence must be written down so that a program can use it. Then the same person, entered twice with "Ann Lee" and "A. Lee", must be found and merged. Some rows break the rules the group trusts, such as a phone code that does not fit the city, and some facts appear with two different values in two sources. This chapter is about the algorithms for each of these steps.

The chapter rests on the theory of chapter 40.1. A mapping between schemas is a set of [tuple-generating dependencies](/tuple-generating-dependency/), the target is built by the [chase](/chase-algorithm/), and most questions about queries come down to [query containment](/query-containment-problem/). The entity-resolution and cleaning parts use probability and approximation as well as logic, and several of their methods are heuristics with no guarantee of a correct answer.

## What the chapter covers

1. **Matching schemas and writing mappings.** [Schema matching](/schema-matching/) guesses which elements of two schemas correspond, and [similarity flooding](/similarity-flooding/) spreads similarity along the structure of the schemas. A [schema mapping](/schema-mapping/) states the correspondence as dependencies, and [GAV and LAV](/gav-and-lav/) are its two simplest forms.
2. **Answering queries using views.** In [answering queries using views](/answering-queries-using-views/) each source is a view and a query must be rewritten over the views. An equivalent rewriting is [NP-complete](/view-rewriting-np-completeness/) to find. The [bucket algorithm](/bucket-algorithm/) and [MiniCon](/minicon-algorithm/) build the maximally contained rewriting, and the [inverse rules algorithm](/inverse-rules-algorithm/) turns the views into Datalog with Skolem terms.
3. **Data exchange.** The [data exchange problem](/data-exchange-problem/) asks for a target instance. The chase gives a [universal solution](/universal-solution/) with labeled nulls, from which the [certain answers](/certain-answers/) of unions of conjunctive queries are read. [Weak acyclicity](/weak-acyclicity/) keeps the chase polynomial, the [core](/data-exchange-core-computation/) is the smallest universal solution, and [composition](/schema-mapping-composition/) chains two mappings and may need second-order dependencies.
4. **Entity resolution.** [Entity resolution](/entity-resolution/) finds the records of one real thing. The [Fellegi-Sunter model](/fellegi-sunter-model/) scores pairs by a likelihood ratio, [blocking](/entity-resolution-blocking/) and the [sorted neighborhood method](/sorted-neighborhood-method/) cut down the pairs, [R-Swoosh](/r-swoosh/) merges records with black-box functions, and [collective entity resolution](/collective-entity-resolution/) uses the links between records.
5. **Constraints, errors and repairs.** [Conditional functional dependencies](/conditional-functional-dependency/) and [denial constraints](/denial-constraint/) state the rules that clean data obeys. A [repair](/database-repair/) is a minimal change that restores them, [consistent query answering](/consistent-query-answering/) returns what holds in every repair, and [HoloClean](/holoclean/) picks likely values with a learned probabilistic model.
6. **Finding dependencies in data.** [Functional dependency discovery](/functional-dependency-discovery/) lists the dependencies that hold in an instance, whose number can be exponential, and [TANE](/tane-algorithm/) does it level by level with stripped partitions.
7. **Truth discovery.** [Truth discovery](/truth-discovery/) picks one value from sources that disagree while it estimates their reliability, and [TruthFinder](/truthfinder/) is an early iterative method for it.

## A first reading

For a first pass, read schema matching, schema mapping, GAV and LAV, answering queries using views, the bucket algorithm, the data exchange problem, universal solutions, certain answers, entity resolution, the Fellegi-Sunter model, blocking, database repairs and functional dependency discovery. These thirteen give the questions of the field and the standard answers.

MiniCon and inverse rules improve on the bucket algorithm and can be read next. The core, composition and consistent query answering hold the deeper theory, and HoloClean, TruthFinder and collective entity resolution the statistical methods; leave them for a second pass.

## Before you start

You need [conjunctive queries](/conjunctive-query/), the [Chandra-Merlin theorem](/chandra-merlin-theorem/), [functional dependencies](/functional-dependency/), [equality-generating dependencies](/equality-generating-dependency/) and [Datalog](/datalog/) from chapter 40.1. The string measures come from Volume 8, mainly the [edit distance](/edit-distance/), and the one-to-one choice of matches is the [assignment problem](/assignment-problem/) of Volume 7, where the [transitive closure](/transitive-closure/) also lives. The Fellegi-Sunter model is a [likelihood ratio test](/likelihood-ratio-test/) from Volume 33. The hardness results use [coNP](/co-np/) from Volume 39 and the repairs use [vertex cover](/vertex-cover/) from Volume 18. Inverse rules use [Skolemization](/skolemization/) from Volume 16, and HoloClean uses the [factor graph](/factor-graph/) of Volume 25 and [Gibbs sampling](/gibbs-sampling/) of Volume 17.
