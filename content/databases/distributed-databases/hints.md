1. The minterm $p_1 \wedge p_2$ holds a and f, $p_1 \wedge \neg p_2$ holds b, $\neg p_1 \wedge p_2$ holds c, and $\neg p_1 \wedge \neg p_2$ holds d and e. Every row satisfies exactly one minterm, so the fragments are complete and disjoint, and their union is Emp. The query reads only the fragment $\neg p_1 \wedge p_2$, since hr rows fail $p_1$.

3. $AA = \begin{pmatrix} 5 & 3 & 2 \\ 3 & 4 & 1 \\ 2 & 1 & 3 \end{pmatrix}$. The bonds are $\mathrm{bond}(A_1, A_2) = 29$, $\mathrm{bond}(A_1, A_3) = 19$ and $\mathrm{bond}(A_2, A_3) = 13$, and $AM$ is twice the sum of the bonds of neighbours: 84 for $A_1A_2A_3$, 96 for $A_2A_1A_3$ and 64 for $A_1A_3A_2$. Inserting $A_3$ into $A_1A_2$ contributes 38 at the left end, 6 in the middle and 26 at the right end, so the algorithm gives $A_3A_1A_2$, the reverse of $A_2A_1A_3$, with $AM = 96$. That is the best of the three orders, and the reversals have the same values.

5. A read needs one copy up and a write needs all $n$. For $n = 3$ the read probability is $1 - 0.01^3 = 0.999999$ and the write probability is $0.99^3 = 0.970299$. For $n = 5$ the write probability falls to $0.99^5 \approx 0.95099$, while a read gets closer still to 1.

6. The bound is $3r + w(2n + 1) = 12 + 2 \cdot 7 = 26$ messages. When the home site is the primary of the items it reads, the reads are local and only the writes cost messages: $14$.

9. Each copy is touched by one transaction only, so the conflict graph over copies has no edges. In one copy, $T_1$ reads the old $x$ that $T_2$ writes, so $T_1$ comes before $T_2$; $T_2$ reads the old $y$ that $T_1$ writes, so $T_2$ comes before $T_1$. Under read-one-write-all, $w_1[y]$ must also write $y_B$, which then conflicts with $r_2[y_B]$, and $w_2[x]$ must write $x_A$, which conflicts with $r_1[x_A]$; the cycle shows up on the copies and two-phase locking at each copy blocks it.

11. Shipping $R_1$ whole costs $2000 \cdot 30 = 60000$. The semijoin ships $R_2[A]$ to site 1 at $100 \cdot 4 = 400$. The selectivity is $100/1000$, so $R_1.A$ keeps $50$ values and $R_1$ keeps $200$ rows, which cost $6000$ to ship. The total is $6400$, so the benefit is $60000 - 6000 = 54000$ against a cost of 400.

12. $S \ltimes R = \{(1,1), (2,4), (3,6)\}$, then $T \ltimes S = \{(1,7), (4,9)\}$, then $S \ltimes T = \{(1,1), (2,4)\}$, then $R \ltimes S = \{(1,1), (2,2)\}$. The join is $\{(1,1,1,7), (2,2,4,9)\}$. The tuple $(3,3)$ of $R$ matches $(3,6)$ of $S$ in the forward pass and goes only when $(3,6)$ has been removed by $T$.

14. The cost of a set $X$ of sites is $|X|$ for storage, plus $2r_j$ for each site $j$ outside $X$, plus 2 times the number of copies away from $j$ for each update. The values are 15 for $\{1\}$, 27 for $\{2\}$, 33 for $\{3\}$, 12 for $\{1, 2\}$, 18 for $\{1, 3\}$, 30 for $\{2, 3\}$ and 15 for $\{1, 2, 3\}$. The cheapest is $\{1, 2\}$.

17. The version of $x$ with timestamp 5 lists $y$ among the items its writer wrote. So the reader knows that $y$ has a version with timestamp 5 and asks the partition of $y$ for exactly that version. A writer makes its versions visible only after every partition has stored them, so the version is there. With $k = 2$ items the read sends $2k$ messages in each of 2 rounds: 6 in all if the second round goes only to $y$, and at most 8.

19. The split $\{a, b, c\}$ and $\{d, e, f\}$ cuts only the edge $c\text{–}d$: cut weight 1, one distributed transaction, and it is the least cut among balanced splits. The split $\{a, b, d\}$ and $\{c, e, f\}$ cuts $a\text{–}c$, $b\text{–}c$, $c\text{–}d$, $d\text{–}e$ and $d\text{–}f$: weight 5, but only 4 distributed transactions, because the first transaction gives two cut edges. The edge weight is a stand-in for the true count.

20. Two sets of sizes $r$ and $w$ in a set of size $n$ meet when $r + w > n$, and two sets of size $w$ meet when $2w > n$. With version numbers, a read takes the newest version among its $r$ copies, which includes a copy the last write reached. Two writes meet at a copy, so their locks there order them, and a read meets each write at a copy too. Every conflict in one copy is then a conflict at some physical copy, so the serialization order of the copies is a valid order of the one-copy history.

21. In a locking system a participant votes no when it hits a deadlock, a lock timeout or a failure that loses its state. In Calvin the order is fixed before execution and locks are taken in that order, so no deadlock arises, and a crashed node replays the same input to the same state. For a data-dependent write set, a reconnaissance read finds the account, the transaction is sent with that write set, and when it runs it checks the row again; if the row changed, it aborts in the same way at every node and is resubmitted.

22. Neither side hears from the other, so each reads 0 and writes 1. When the partition heals, the replicas must merge two writes of 1. If the merge keeps 1, one increment is lost. Any serial order would end at 2, so keeping 1 is not serializable, and producing 2 from two blind writes of 1 needs knowledge the writes do not carry. An increment operation that merges by adding, as in a counter CRDT, avoids the problem.

23. Without splitting, one node receives $10000 + 100 = 10100$ tuples and makes $10^6$ output tuples. After the split each node holds $1000$ of the $R$ tuples and all $100$ $S$ tuples, so its load is $1100$ and its output $10^5$. The broadcast costs $100 \cdot 9 = 900$ extra tuples. Each pair of an $R$ tuple and an $S$ tuple with the key meets at exactly one node, the node of the $R$ tuple, so each output tuple is made once.
