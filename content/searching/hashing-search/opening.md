Sorting buys a search of $\lg n$ comparisons. Hashing buys a search of a constant number of probes on average, by giving up order altogether. A hash function turns the key into an array index, and the search goes straight to that slot. When two keys want the same slot, the table needs a rule to keep both, and the cost of a search is the cost of that rule. How large the cost is depends on how the hash values spread over the slots, and much of the theory of hashing is about stating that spread exactly and proving what follows from it.

Volume 3 builds hash tables as data structures. This chapter looks at them as search methods: what a search costs, under which assumption, and how close to one probe it can get. It starts with the tables where a search reads exactly one slot, proves the expected costs of chaining and of open addressing, and ends with two settings, board games and growing files, where the shape of the problem changes the shape of the hash.

## What the chapter covers

The chapter is in four groups, read in order.

1. **Tables without collisions.** A [direct-address table](/direct-address-table/) gives each possible key its own slot, which works only for small universes. A [perfect hash function](/perfect-hash-function/) gives the same one-probe search for a fixed set of keys, and a [minimal perfect hash function](/minimal-perfect-hash-function/) does it with no empty slots and about $1.443$ bits per key.
2. **Chaining and the cost of a search.** The [simple uniform hashing assumption](/simple-uniform-hashing/) is the model behind the classic bounds. Under it, the [expected search time with chaining](/chaining-expected-search-time/) is $\Theta(1 + \alpha)$ for a load factor $\alpha$. The [universal hashing lemma](/universal-hashing-lemma/) proves the same bound for every set of keys, with the randomness in the choice of the function.
3. **Open addressing and clustering.** Linear probing suffers from [primary clustering](/primary-clustering/), where runs of full slots grow and merge. Quadratic probing keeps [secondary clustering](/secondary-clustering/), where keys with one home slot repeat each other's probes. The [expected probes in open addressing](/open-addressing-expected-probes/) without any clustering are $1/(1 - \alpha)$ for an unsuccessful search and about $(1/\alpha)\ln(1/(1 - \alpha))$ for a successful one.
4. **Hashing for special settings.** [Zobrist hashing](/zobrist-hashing/) hashes a board position and updates the hash with a few XORs per move. [Dynamic hashing](/dynamic-hashing/) grows a table one bucket at a time, which suits files on disk.

## A first reading

For a first reading, take these eight entries in order: [direct-address table](/direct-address-table/), [perfect hash function](/perfect-hash-function/), [simple uniform hashing](/simple-uniform-hashing/), [expected search time with chaining](/chaining-expected-search-time/), [universal hashing lemma](/universal-hashing-lemma/), [primary clustering](/primary-clustering/), [expected probes in open addressing](/open-addressing-expected-probes/) and [Zobrist hashing](/zobrist-hashing/). In each theorem, look first at what is random: the keys, or the hash function. A bound that holds when the keys are random says nothing about keys chosen by an adversary, while a bound over a random choice of the function holds for every input. The tables of numbers in the two theorems on expected costs are worth checking by hand for one load factor.
