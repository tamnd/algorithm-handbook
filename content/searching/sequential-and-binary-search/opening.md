To search is to find where a key is, or to learn that it is not there. A program that looks up a word in a spelling list, a database that finds a row by its index, a version control tool that finds the first commit where a test fails: each one searches. How fast it can search depends on what it knows about the data. If the items are in no order, every item may be the one, and the only method is to look at them all. If the items are sorted, one comparison with the middle item tells which half to keep, and a million items need only twenty comparisons.

This chapter is about these two cases and the space between them. It starts with the scan, moves to [binary search](/binary-search/) and its many forms, and then shows how far the halving idea reaches: to arrays that are only partly sorted, to matrices, and to arrays whose length is not known. It ends with the proof that binary search cannot be beaten by any comparison method, and with the tricks that make it fast on a real processor.

## What the chapter covers

The chapter is in six groups, read in order.

1. **Searching by scanning.** [Search in an unordered array](/search-in-unordered-array/) needs $n$ comparisons in the worst case, and [linear search](/linear-search/) makes exactly that many. A [sentinel](/sentinel-search/) removes the end test from the loop. [Finding the maximum](/find-maximum/) costs exactly $n - 1$ comparisons. A [self-organizing list](/self-organizing-list-search/) moves the items that are asked for often to the front.
2. **Binary search and its boundaries.** [Binary search](/binary-search/) with its loop invariant, then the [lower bound query](/lower-bound-query/) and the [upper bound query](/upper-bound-query/), which find the first position where a test becomes true. One loop of five lines, given in [lower and upper bound search](/lower-and-upper-bound-search/), answers both.
3. **Other ways to probe a sorted array.** [Jump search](/jump-search/) moves only forward. [Exponential search](/exponential-search/) costs $O(\log i)$ for a key at index $i$ and solves [unbounded search](/unbounded-search/). [Interpolation search](/interpolation-search/) guesses the position from the value and needs $O(\log \log n)$ probes on average on uniform keys.
4. **Search beyond a plain sorted array.** Halving still works on a [rotated sorted array](/rotated-sorted-array-search/), for [peak finding](/peak-finding/), for the [median of two sorted arrays](/median-of-two-sorted-arrays/) and, with a different walk, in a [row- and column-sorted matrix](/sorted-matrix-search/).
5. **How many comparisons.** The [decision tree for search](/search-decision-tree/) and the [lower bound](/search-lower-bound/) of $\lceil \lg(n+1) \rceil$ comparisons.
6. **Binary search on real machines.** [Fibonacci search](/fibonacci-search/), [uniform binary search](/uniform-binary-search/), [branchless binary search](/branchless-binary-search/) and the [Eytzinger layout](/eytzinger-layout/) make the same number of comparisons as binary search but spend less time on each.

For a first reading, take these twelve entries in order: [search in an unordered array](/search-in-unordered-array/), [linear search](/linear-search/), [search in a sorted array](/search-in-sorted-array/), [binary search](/binary-search/), [lower bound query](/lower-bound-query/), [lower and upper bound search](/lower-and-upper-bound-search/), [first and last occurrence](/first-and-last-occurrence/), [exponential search](/exponential-search/), [interpolation search](/interpolation-search/), [minimum of a rotated sorted array](/rotated-sorted-array-minimum/), [peak finding](/peak-finding/) and [staircase search](/staircase-search/). Read the correctness section of binary search slowly: almost every bug in a binary search is a broken invariant, and the half-open range used throughout the chapter is the easiest one to keep. The last two groups, and the proof of the expected time of interpolation search, can wait for a second pass.
