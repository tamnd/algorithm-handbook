The STM then also sees write-write conflicts between $T_1$ and $T_2$ on stripe 1 ($b$ and $d$) and between $T_1$ and $T_3$ on stripe 0 ($c$ and $a$), and it sees $T_2$ and $T_3$ conflict on both stripes ($c$ with $a$, $d$ with $b$). 4. The hold time is $3 + 3k = 24$ steps under write-back, 25 under write-through and 3 under TL2. The whole solo run takes $9 + 3k = 30$ steps.

6. Karma waits $d + 1 = 5$ intervals. Polite takes 3 waits and $2^3 - 1 = 7$ steps; Polka takes 4 waits and $2^4 - 1 = 15$ steps. The expected spin times are $(2^{10} - 1) \cdot 2^4 = 16368$ ns for Polite and $(2^4 - 1) \cdot 2^4 = 240$ ns for Polka. Greedy's factor is $4 \cdot 5 + 2 = 22$.

7. `0x6` has bits 1 and 2: a conflict, with the retry bit set, so retry. `0x8` has bit 3: the transaction overflowed the cache, so take the fallback. `0x2A000001` has bit 0: an explicit XABORT with code $\mathtt{0x2A} = 42$; the retry bit is always clear here, and the code decides what to do. `0x0` has no bit set, as after CPUID, and a retry will abort again. `0x24` has bits 2 and 5: a conflict inside a nested transaction, with no promise that a retry succeeds.

9. $H_2$ is not opaque, and the first bad prefix ends at $T_1$'s read of $y$. $T_1$ read $x = 0$, so it comes before $T_2$. $T_3$ read $x = 1$, so $T_2$ comes before $T_3$. $T_1$ read $y = 1$, so $T_3$ comes before $T_1$. That is a cycle. The committed part, $T_2$ then $T_3$, is strictly serializable. If $T_1$ committed, the same cycle would make the history not serializable. $H_3$ is not serializable, since in either order the second transaction should read the first one's write. Snapshot isolation allows it: both transactions read the initial snapshot and their write sets $\{y\}$ and $\{x\}$ are disjoint. This is write skew.

11. Schedule A: TL2 aborts $R$, because the version of $y$ is newer than $rv$. TinySTM finds $x$ unchanged, extends the snapshot and commits with $(0, 1)$, and NOrec revalidates $x$ by value and also commits with $(0, 1)$; the serial order is the writer, then $R$. Schedule B: all three abort, because $x$ really changed. Schedule C: TL2 and TinySTM abort, because the version of $x$ changed. NOrec sees $x = 0$ again and commits with $(0, 1)$, in the order $W_1, W_2, R$.

14. Under Greedy, $T_0$ aborts the younger $T_1$ at turn 4, $T_2$ waits for the older $T_0$ at turn 6, and $T_0$ commits at turn 7. Then $T_1$ aborts the younger $T_2$ at turn 10, $T_1$ commits at turn 12 and $T_2$ at turn 15: the order is $T_0, T_1, T_2$, with two aborts. Under Aggressive, $T_0$ aborts $T_1$ (turn 4), $T_2$ aborts $T_0$ (turn 6), $T_2$ commits (turn 9), $T_0$ aborts $T_1$ again (turn 12), and $T_0$ and $T_1$ commit at turns 14 and 17: the order is $T_2, T_0, T_1$, with three aborts.

19. Let $T_1$ write $x$ then $y$ and $T_2$ write $y$ then $x$. In lockstep, each takes its first lock, finds its second lock owned, aborts, releases, and restarts in the same rhythm; a simulation of 300 turns gives 150 aborts and no commit. In address order both try $x$ first, the loser aborts at once, and the winner commits. For NOrec, a transaction aborts only when value validation finds a changed word, so some writer has finished a write-back after its snapshot. A failed commit CAS means that another writer won the CAS, and a writer that wins the CAS always commits.

20. NOrec gives $\{1, 101\}$, and TL2 gives $\{1, 100, 101\}$. In NOrec, a writer copies its values only while the sequence lock is odd, and no transaction can begin or commit until the lock is even again. So thread 2's write-back ends before thread 1's transaction commits, and the plain accesses come after it.

21. Every update transaction in TL2 writes the global clock, and every transaction reads it, whatever its data set. So TL2 is not strictly data-partitioned, and the bound needs that hypothesis. The price is one shared counter on which all commits contend. A multi-version STM keeps several versions of each object, so a read finds the version for $rv$ in one look, with no validation. It breaks the single-version hypothesis.

22. In $E$, $T_2$ moves the clock to 1 and gives $X_2$ version 1. Then $T_0$ starts with $rv = 1$ and reads $X_1 = 0$, $T_1$ commits with version 2, and $T_0$ reads $X_2 = 1$ (version $1 \le rv$) and commits. The serial order is $T_2, T_0, T_1$. In $E'$, $T_0$ starts with $rv = 0$ and reads $X_1 = 0$. Then $T_1$ commits with version 1 and $T_2$ with version 2, and $T_0$ meets $X_2$ at version $2 > rv$ and aborts. Step 2 of the proof fails: $\alpha_1$ reads the clock and $\delta_2$ increments it, so the two fragments contend although $T_0$ and $T_2$ are disjoint-access. TL2 is not weak DAP, and in $E'$ its read-only transaction aborts as well.
