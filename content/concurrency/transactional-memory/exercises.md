1. ◦ Three transactions run at the same time. $T_1$ reads $a$ and writes $b$ and $c$; $T_2$ reads $c$ and writes $d$; $T_3$ reads $b$ and writes $a$. List every pair that conflicts and the word and kind (read-write, write-read, write-write) of each conflict. Then put the words at addresses $a = 0$, $b = 1$, $c = 2$, $d = 3$ and let the STM keep one lock per stripe, with stripe $= $ address mod 2. Which conflicts does the STM now see, and which of them are false?

2. ◦ A transaction reads 6 distinct words and writes one. How many checks does it do under incremental validation, and how many under the clock policy? The validation entry gives the shared steps of a solo run as $3r + r(r-1)/2 + 4 + r$ for the incremental policy and $3r + r + 6$ for the clock policy. Evaluate both for $r = 6$, and give the incremental count again for a read-only transaction of 6 reads.

3. ◦ A global version clock gains 1 at each update commit, and a machine commits $10^7$ update transactions per second. How long until a 32-bit clock wraps around? A 48-bit clock?

4. ◦ A transaction reads $a_0$, writes $a_0 \leftarrow a_0 - 1$, and then reads $k = 7$ more words. In the solo-run model of the encounter-time locking entry, for how many shared steps does it hold the lock of $a_0$ under TinySTM write-back, TinySTM write-through and TL2? How many steps does the whole solo run take in TL2?

5. ◦ In the Shavit-Touitou STM, an attempt with no conflict on a data set of $k$ words, $w$ of them written, takes $8k + 3w + 4$ steps. Find the cost for $k = 3$ with $w = 2$ and with $w = 3$. In DSTM, how many read-table checks does a transaction do that opens 5 objects for reading and commits, and how many CAS steps does one that opens 2 objects for writing do?

6. ◦ A transaction $A$ meets an enemy $B$ that has stopped and holds the object for ever, and $B$'s priority is 4 above $A$'s. In the models of the entries, how many backoff intervals does Karma wait before it aborts $B$? How many waits and backoff steps do Polite with $m = 3$ and Polka take? With $k = 4$, what is the expected total spin time of Polite with $m = 10$, and of Polka here? Finally, what is the makespan factor $s(s+1)+2$ of Greedy for $s = 4$ shared objects?

7. ◦ Decode these values of the EAX register after an RTM abort, and say for which of them a retry in hardware is worth trying: `0x6`, `0x8`, `0x2A000001`, `0x0`, `0x24`.

8. ◦ A transaction writes $x, y, x, z, x, y$ in that order. Count the stores to shared memory if it commits and if it aborts, under (a) a redo log with one entry per word; (b) an undo log that saves each word once, at its first write; (c) an undo log that saves an entry at every write.

9. • History $H_2$: $T_1$ reads $x \to 0$; $T_2$ writes $x = 1$ and commits; $T_3$ reads $x \to 1$, writes $y = 1$ and commits; $T_1$ reads $y \to 1$ and aborts. Is $H_2$ opaque, and if not, at which event does the first non-opaque prefix end? Is the history of its committed transactions strictly serializable? Would the history be serializable if $T_1$ committed instead? History $H_3$: $T_1$ reads $x \to 0$, $T_2$ reads $y \to 0$, $T_1$ writes $y = 1$, $T_2$ writes $x = 1$, and both commit. Is it serializable, and would snapshot isolation allow it?

10. • A transaction runs `(A) orElse (B)`. Branch $A$ reads $x$, calls `retry` if $x = 0$ and otherwise sets $x \leftarrow x - 1$; branch $B$ does the same with $y$. It starts with $x = y = 0$. What is its wait set? Another thread then commits $z \leftarrow 1$; later a third thread commits $y \leftarrow 1$. Say after which commit the transaction runs again, what each branch does, and the final values of $x$ and $y$.

11. • Memory holds $x = y = 0$. A reader $R$ reads $x$ and then $y$, and writers commit between its two reads. In schedule A, one writer sets $y = 1$. In schedule B, one writer sets $x = 1$ and $y = 1$. In schedule C, one writer sets $x = 1$ and $y = 1$, and then a second sets $x = 0$. For each schedule, say whether $R$ commits under TL2, TinySTM and NOrec, and what it returns when it does. Check each commit against a serial order.

12. • In a multi-version STM, a transaction $R$ starts with $rv = 10$ and reads $a$. Update transactions then commit at times 11, 12 and 13, each writing $b$, whose previous version has time 5. Then $R$ reads $b$. (a) With the policy "keep the newest $k$", what is the smallest $k$ for which $R$ does not abort? (b) Under "keep what live transactions need", how many versions of $b$ are kept when $R$ reads it? (c) Suppose $R$ also writes a word $c$. What happens at its commit?

13. • In Hybrid NOrec, memory starts with $a = 0$ and SEQ $=$ HWC $= 0$. A software transaction $T$ runs $a \leftarrow a + 1$ and a hardware transaction $H$ runs $a \leftarrow a + 5$. $T$ reads $a$; then $H$ runs and commits; then $T$ commits. Trace the run with the check of HWC at the software commit removed, and then with it. Why do $T$'s checks after each read not catch $H$?

14. • Three transactions open objects for writing: $T_0$ opens $x$ then $y$, $T_1$ opens $y$ then $z$, $T_2$ opens $z$ then $x$. Their timestamps are 0, 1 and 2, and a smaller one is older. They take turns in the order $T_0, T_1, T_2$, and a turn is one action: open the next object, commit when both are open, wait, or restart after an abort. An aborted transaction loses its objects and spends its next turn on the restart; a committed one releases its objects and takes no more turns. Run Greedy, then Aggressive, which always aborts the owner. Give the commit order, the number of turns of uncommitted transactions until the last commit, and the aborts.

15. • A DSTM transaction searches a sorted list of $n = 10$ nodes and opens every node for reading. How many read-table checks does it do, at its opens and at commit? Now it releases node $i - 1$ just before it opens node $i + 1$, so its table never holds more than two nodes. Count again, and give the general count for $n$ nodes. Which changes made by other transactions does the second search fail to notice, and when does that matter?

16. • A boosted set starts as $\{5\}$, with one abstract lock per key. A transaction $T$ calls `add(3)`, `add(5)`, `remove(5)` and `contains(3)`, and then aborts. Give the result of each call, the undo log, the order in which the inverses run and the final set. While $T$ runs, another transaction calls `contains(4)` and a third calls `add(5)`: which of them must wait?

17. • An STM maps words to $s$ stripes with a hash that behaves like a uniform random function. A reader reads $r$ words and a concurrent writer writes one other word. Find the probability of a false conflict for $s = 1024$ with $r = 10$ and with $r = 100$. What is the smallest power of two $s$ that keeps the probability for $r = 100$ below 1%?

18. ★ Write an opacity checker for small histories. It should try every serial order of the transactions, every completion of the commit-pending ones, and every prefix of the history. Run it on two histories. In $H_a$, $T_1$ writes $x = 1$ and invokes tryC with no response; $T_3$ reads $x \to 0$; $T_2$ reads $x \to 1$ and commits; $T_3$ commits. In $H_b$, $T_1$ writes $x = 1$ and invokes tryC with no response; $T_2$ reads $x \to 1$ and commits; then $T_3$ begins, reads $x \to 0$ and commits. Which is opaque, with which order, and where does the other first fail?

19. ★ The TL2 entry says that TL2 can livelock but gives no schedule. Assume that a committer locks its write set in program order and aborts at once on an owned lock. Give a schedule of two transactions that never commits, and show that locking in address order removes it. Then prove that NOrec cannot livelock: in every run, if some transaction aborts, some other transaction commits.

20. ★ Take the privatization idiom, with a flag `priv` and a word $x$, both 0 at the start. Thread 1 runs `atomic { priv ← 1 }`, then reads $x$ and writes $x + 1$ with plain accesses. Thread 2 runs `atomic { if priv = 0 then x ← 100 }`. Model NOrec and TL2 at the level of single shared steps, enumerate all interleavings, and give the set of final values of $x$ for each. Explain the result for NOrec with one sentence about its sequence lock.

21. ★ Guerraoui and Kapałka proved that some read of a $k$-object transaction needs $\Omega(k)$ steps in an opaque, progressive TM with invisible reads that keeps one version per object and is strictly data-partitioned. TL2 with one lock per word is opaque, keeps one version, has invisible reads, and aborts a transaction only on a conflict with a concurrent one, yet each read takes $O(1)$ steps. Explain why there is no contradiction, and why a multi-version STM escapes the bound for a different reason.

22. ★ Run the proof of the disjoint-access-parallel lower bound against TL2. Write down what $T_0$, $T_1$ and $T_2$ do in TL2 in the executions $E = \delta_2 \cdot \alpha_1 \cdot \delta_1 \cdot \alpha_2$ and $E' = \alpha_1 \cdot \delta_1 \cdot \delta_2 \cdot \alpha_2$. What does $T_0$ return in each, which step of the proof fails, and which hypothesis of the theorem does TL2 break?
