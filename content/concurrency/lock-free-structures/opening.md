Two threads add one to a shared counter. Each reads the counter and then writes back the value plus one. If both read 0 before either writes, both write 1, and one increment is lost. Of the six ways to interleave the two reads and the two writes, four end at 1. A lock fixes this, but a lock brings its own trouble: if the thread that holds it is descheduled or crashes, every other thread waits. The structures of this chapter use no locks. A thread reads the counter, computes the new value, and installs it with one [compare-and-swap](/compare-and-swap/) that succeeds only if the counter still holds the value it read. If the CAS fails, some other thread has just made progress, and the first thread tries again. With three threads that each add one this way, all 498 complete schedules end at 3.

The same pattern builds whole data structures. The [Treiber stack](/treiber-stack/) is a linked list whose top pointer changes only by CAS: a push links a new node in front of the top it read, a pop swings the top to the second node. The [Michael-Scott queue](/michael-scott-queue/) does the same with two pointers and a dummy node. Harder cases need more ideas: a linked list cannot delete a node with one CAS without losing a concurrent insert, so the [Harris list](/harris-linked-list/) first marks the node and only then unlinks it.

Two questions run through the chapter. The first is what a correct result is when operations overlap in time; the answer used everywhere is [linearizability](/linearizability/). The second is who is sure to finish. A lock-free structure guarantees that some operation completes; a wait-free one guarantees that every operation does, in a bounded number of its own steps. Behind both sits a theory that says which atomic instructions can build which objects at all, and why compare-and-swap is enough for everything.

## What the chapter covers

The chapter is in nine groups, read in order.

1. **What correct means.** [Non-blocking algorithms](/non-blocking-algorithm/) in general, [linearizability](/linearizability/) as the safety condition, and the [linearization point](/linearization-point/) as the tool of every proof in the chapter.
2. **Atomic primitives.** [Compare-and-swap](/compare-and-swap/), [load-linked/store-conditional](/load-linked-store-conditional/), [fetch-and-add](/fetch-and-add/), and the two-word [double compare-and-swap](/double-compare-and-swap/), with what real hardware gives.
3. **Progress conditions.** [Lock-freedom](/lock-freedom/), [wait-freedom](/wait-freedom/) and [obstruction-freedom](/obstruction-freedom/): what each one promises, and runs that separate them.
4. **Stacks and queues.** The Treiber stack and the Michael-Scott queue, the [elimination back-off stack](/elimination-backoff-stack/), and the [Herlihy-Wing queue](/herlihy-wing-queue/), whose operations have no fixed linearization point.
5. **Ring buffers and work-stealing deques.** The [Lamport queue](/lamport-spsc-queue/), wait-free with no CAS at all, the [Vyukov bounded queue](/vyukov-bounded-mpmc-queue/), and the [Chase-Lev](/chase-lev-deque/) and [ABP](/arora-blumofe-plaxton-deque/) deques used by work-stealing schedulers.
6. **Lists, sets and maps.** [Logical deletion](/logical-deletion/), the Harris list, and what is built from it: the [Michael hash table](/michael-hash-table/), the resizable [split-ordered list](/split-ordered-list/), the [lock-free skip list](/lock-free-skip-list/) and a [priority queue](/lock-free-priority-queue/) on top of it.
7. **The consensus hierarchy.** The [consensus number](/consensus-number/) of an object, [read-modify-write](/read-modify-write/) operations, and the two end points: [registers have consensus number one](/registers-have-consensus-number-one/), and [CAS has consensus number infinity](/cas-has-infinite-consensus-number/).
8. **Helping and universality.** [Helping](/helping/) as a pattern, [multi-word CAS](/multi-word-cas/), the [universal construction](/universal-construction/), the [Kogan-Petrank](/kogan-petrank-queue/) wait-free queue, the [non-blocking binary search tree](/non-blocking-bst/), and [flat combining](/flat-combining/) as the blocking alternative.
9. **Snapshots and counting.** The [atomic snapshot](/atomic-snapshot/) problem and the [wait-free solution of Afek et al.](/afek-atomic-snapshot/), and [counting networks](/counting-network/), with the [bitonic network](/bitonic-counting-network/) in full.
