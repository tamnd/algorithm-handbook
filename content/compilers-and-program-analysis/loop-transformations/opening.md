Take the nest `for i = 1 to 4: for j = 1 to 4: A[i][j] = A[i-1][j+1] + 1`, with `A[i][j]` set to $10i + j$ at the start. Iteration $(1, 2)$ stores $4$ in `A[1][2]`, and iteration $(2, 1)$ then reads that 4 and stores 5. Swap the two loops so that $j$ is outer, and iteration $(2, 1)$ runs before $(1, 2)$: it reads the old value 12 and stores 13. Nine of the sixteen elements end up different. The cause is a single dependence with distance $(1, -1)$. Interchange turns it into $(-1, 1)$, which points backward in time. Skew the inner index first, $j' = j + i$, and the distance becomes $(1, 0)$. Interchange then gives $(0, 1)$, which is legal, and the new outer loop carries no dependence, so its iterations can run in parallel.

The whole chapter works this way. A compiler reorders the iterations of a loop nest to use the cache, the vector unit or several processors, and the [data dependences](/data-dependence/) of the nest decide which orders keep the meaning. The results come in three kinds, and each entry says which kind it gives. Some are exact: the [legality theorem](/loop-transformation-legality/) shows that a reordering is safe when every distance stays lexicographically positive, a condition that is sufficient but not necessary; the [Omega test](/omega-test/) decides integer linear constraints exactly, in exponential time in the worst case; and [array dataflow analysis](/feautrier-array-dataflow/) finds the exact source of each read, but only for static control parts with affine bounds and subscripts. Some are conservative: the [GCD test](/gcd-test/) and the [Banerjee test](/banerjee-test/) can report a dependence that does not exist, and never miss one that does. The rest are choices made by a cost model or a heuristic, such as the schedules of [Pluto](/pluto-algorithm/), the transformations of the [Wolf-Lam algorithm](/wolf-lam-locality-algorithm/) and the packs of [SLP vectorization](/slp-vectorization/). Their speedups are measurements on named benchmarks, not guarantees.

Neighbouring topics have their entries elsewhere in this volume. [Natural loops](/natural-loop/) and the [control flow graph](/control-flow-graph/) are in Chapter 34.2, Intermediate representations. [Strength reduction](/strength-reduction/) and [loop-invariant code motion](/loop-invariant-code-motion/) are in Chapter 34.4, Optimizations. [Software pipelining](/software-pipelining/) and [iterative modulo scheduling](/iterative-modulo-scheduling/), which overlap the iterations of an inner loop on one processor, are in Chapter 34.6, Code generation and JIT compilation. The [alias analysis](/alias-analysis/) that tells whether two pointers name one array is in Chapter 34.7. This chapter links to those entries and does not repeat them.

## What the chapter covers

The chapter is in seven groups, read in order.

1. **Dependences.** Data dependence, the [distance vector](/dependence-distance-vector/) and the [direction vector](/dependence-direction-vector/), [loop-carried dependence](/loop-carried-dependence/), the legality theorem and the [DOALL loop](/doall-loop/).

## A first reading

Take these twelve entries in order: data dependence, the dependence distance vector, loop-carried dependence, the legality theorem and the DOALL loop; dependence testing and the GCD test; loop interchange, loop distribution, loop skewing and loop tiling; and the Allen-Kennedy algorithm. Together they show what a dependence is, how a compiler tests for one, when the common transformations are legal, and how a loop becomes vector code.

Direction vectors, the Banerjee and subscript-wise tests, induction variables, the vector and parallel group after Allen-Kennedy, the unimodular group and the polyhedral group can wait for a second pass. The polyhedral entries need linear programming and Farkas' lemma.

## Before you start
