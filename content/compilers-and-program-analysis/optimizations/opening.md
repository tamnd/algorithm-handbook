Take a basic block that computes `p = x * y`, `q = y * x`, `r = p - q`, `s = z + r`, then `x = 4`, `t = x * y`, `u = x * 3` and `v = t - p`. [Local value numbering](/local-value-numbering/) gives `x * y` and `y * x` the same number, so `q` becomes the copy `q = p`. Then `r` is known to be zero, `s` becomes the copy `s = z`, and after `x = 4` the product `u = x * 3` folds to the constant 12. The product `t = x * y` must stay, because `x` has changed since `p` was computed. If `q` and `r` are not read after the block, [dead code elimination](/dead-code-elimination/) then removes them. No single pass did all of this. Each rewrite made the next one possible, and that is how real optimizers work: many small passes, each correct by itself, run in a sequence and often more than once.

An optimization must keep the behavior of the program on every input, and it should make the program faster or smaller on the inputs that matter. The first part is a proof obligation. The second is usually a measurement. Most of the facts an optimizer would like to know are undecidable: whether an instruction ever executes, or whether two expressions always have the same value. So every pass in this chapter acts only on facts that a conservative analysis can prove, and it misses some opportunities. The [full employment theorem](/full-employment-theorem/) makes this exact: no algorithm maps every program to a smallest equivalent one, so every optimizer can be improved. The last group of the chapter shows what can still be done on short loop-free code, where an exhaustive or random search can find the best program.

## What the chapter covers

The chapter has nine groups, read in order.

1. **Local cleanups.** [Constant folding](/constant-folding/), [peephole optimization](/peephole-optimization/), local value numbering and [copy propagation](/copy-propagation/).
2. **Removing dead code.** Dead code elimination by liveness, and [aggressive dead code elimination](/aggressive-dead-code-elimination/), which marks useful code through control dependence.
3. **Finding equal values.** [Common subexpression elimination](/common-subexpression-elimination/), the [global value numbering](/global-value-numbering/) problem and the [Alpern-Wegman-Zadeck algorithm](/alpern-wegman-zadeck-value-numbering/).
4. **Moving code.** [Loop-invariant code motion](/loop-invariant-code-motion/), [partial redundancy elimination](/partial-redundancy-elimination/), [lazy code motion](/lazy-code-motion/) and [SSAPRE](/ssapre/).
5. **Cheaper operations in loops.** [Strength reduction](/strength-reduction/) and [operator strength reduction on SSA](/operator-strength-reduction/).
6. **Across procedure boundaries.** [Function inlining](/function-inlining/), [tail call optimization](/tail-call-optimization/), [devirtualization](/devirtualization/), [interprocedural constant propagation](/interprocedural-constant-propagation/) and [scalar replacement of aggregates](/scalar-replacement-of-aggregates/).
7. **Using profiles.** [Profile-guided optimization](/profile-guided-optimization/), [Ball-Larus path profiling](/ball-larus-path-profiling/) and [Pettis-Hansen code positioning](/pettis-hansen-code-positioning/).
8. **Specialization and fusion.** [Partial evaluation](/partial-evaluation/), [binding-time analysis](/binding-time-analysis/), the [Futamura projections](/futamura-projections/), [deforestation](/deforestation/) and [supercompilation](/supercompilation/).
9. **Limits and search.** The full employment theorem, [superoptimization](/superoptimization/), [equality saturation](/equality-saturation/) and [stochastic superoptimization](/stochastic-superoptimization/).

## A first reading

Take these eleven entries in order: constant folding, local value numbering, dead code elimination, common subexpression elimination, loop-invariant code motion, partial redundancy elimination, strength reduction, function inlining, profile-guided optimization, partial evaluation and the full employment theorem. They give one pass of each kind: a local rewrite, a deletion, a reuse, a motion, a cheaper operation, a change across calls, a use of measured frequencies and a specialization, and then the theorem that says why none of them can be perfect.

On a second pass, read the algorithms that make these passes exact or fast: the Alpern-Wegman-Zadeck algorithm after global value numbering, lazy code motion after partial redundancy elimination, and operator strength reduction after strength reduction. Ball-Larus path profiling and Pettis-Hansen code positioning belong to the back end and can wait. Binding-time analysis, the Futamura projections, supercompilation and the three search methods of the last group are advanced; read them when the earlier entries feel familiar.
