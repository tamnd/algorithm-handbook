A hash table finds a key in constant expected time, but it cannot say which key comes next. Many programs need exactly that. A database index answers "all orders between March and May". A calendar asks for the next free slot after 10:00. An event simulator removes the event with the next time stamp, and a text editor keeps its lines in order while they change. These are questions about order, and the structure that answers them is the search tree. The [ordered set](/ordered-set/) is the abstract type: a [dictionary](/dictionary/) that also returns the minimum, the successor, the rank of a key and the largest key not above a query.

The [binary search tree](/binary-search-tree/) stores the keys in a binary tree so that every key in a left subtree is smaller than its ancestor and every key in a right subtree is larger. Each operation then follows a single path from the root, so it costs $\Theta(h)$, where $h$ is the height. The height is at least $\lfloor \lg n \rfloor$ and at most $n - 1$, and the whole chapter is about that gap. Keys in random order give a short tree; keys in sorted order give a path. This chapter studies the plain tree, what randomness does to it, how to build the best tree for known search frequencies, and how a tree that reshapes itself on each access can do almost as well as any tree. Trees that keep their height small by explicit rules, such as AVL and red-black trees, are the subject of Chapter 3.4.

## What the chapter covers

The chapter is in seven groups, read in order.

1. **Ordered sets.** The [ordered set](/ordered-set/), the [ordered symbol table](/ordered-symbol-table/) that adds a value to each key, and the [floor and ceiling](/floor-and-ceiling-in-ordered-set/) queries.
2. **The binary search tree.** The [order rule](/binary-search-tree-property/), the [tree](/binary-search-tree/) itself, and its [search](/bst-search/), [insertion](/bst-insertion/), [deletion](/bst-deletion/) and [floor and ceiling](/bst-floor-and-ceiling/), each in $\Theta(h)$ time.
3. **More in each node.** The [threaded tree](/threaded-binary-tree/), which walks in order without a stack, and the general method of [augmenting](/augmenting-data-structures/) a tree with a summary of each subtree.
4. **Random trees and skip lists.** The [random binary search tree](/random-binary-search-tree/), whose nodes have [expected depth](/random-bst-expected-depth/) about $2 \ln n \approx 1.39 \lg n$, and the [skip list](/skip-list/), which gets the same expected costs from coin flips.
5. **Trees for known frequencies.** The [expected search cost](/expected-search-cost-bst/) of a tree, and the [dynamic program](/optimal-bst-dynamic-programming/) that minimizes it in $\Theta(n^2)$ time with Knuth's speed-up.
6. **Self-adjusting trees.** [Splaying](/splaying/) and the [splay tree](/splay-tree/), with $O(\log n)$ amortized cost, the [static optimality](/static-optimality-theorem/) and [working set](/working-set-theorem/) theorems, the open [dynamic optimality conjecture](/dynamic-optimality-conjecture/), and the [tango tree](/tango-tree/), which is $O(\log \log n)$-competitive.
7. **Beyond the logarithm.** The [finger search tree](/finger-search-tree/), which searches in $O(\log d)$ time for a key $d$ places from a known one, the [predecessor problem](/predecessor-problem/) on integer keys, and the [fusion tree](/fusion-tree/), which answers it in $O(\log n / \log w)$ time.
