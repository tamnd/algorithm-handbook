A compiler looks up every name it reads in a table of symbols. A web server looks up every session by its cookie, a spelling checker looks up every word, and a program that counts words looks up each word to add one to its count. All of them need the same three operations on a set of keys: insert a key, delete it, and find it. A sorted array or a balanced search tree does each in $O(\log n)$ time. A hash table does each in $O(1)$ expected time, and that is why it is one of the most used structures in programs.

The idea is to compute where a key belongs instead of searching for it. A [hash function](/hash-function/) turns the key into an index of an array of $m$ slots, and the key is stored there. Two keys can land in the same slot, and since the keys come from a universe far larger than $m$, they will. Everything else in the chapter is about this [collision](/hash-collision/): how to resolve it, how often it happens, and how to make it rare whatever the input. The answer depends on the [load factor](/load-factor/) $\alpha = n/m$, the number of keys per slot. With [separate chaining](/separate-chaining/) a failed search looks at $\alpha$ keys on average; with [linear probing](/linear-probing/) it takes $\frac12(1 + 1/(1-\alpha)^2)$ probes, which is 2.5 at $\alpha = 1/2$ and 50.5 at $\alpha = 0.9$.

These averages assume that the hash function spreads the keys well. A fixed function has bad inputs, and an attacker who knows the function can send them. The cure is to pick the function at random from a [universal family](/universal-hash-family/), so that the bounds hold in expectation for every input. When even expected bounds are not enough, [cuckoo hashing](/cuckoo-hashing/) answers every search with two probes, and [perfect hashing](/perfect-hashing/) stores a fixed set with no collisions at all.

## What the chapter covers

The chapter is in nine groups, read in order.

1. **The dictionary problem.** The [problem](/dictionary-problem/) of insert, delete and find, and the [dictionary](/dictionary/) as an abstract type.
2. **Hash functions and collisions.** The [hash function](/hash-function/), [collisions](/hash-collision/), and the [division](/division-method/) and [multiplication](/multiplicative-hashing/) methods.
3. **The hash table and its load.** The [hash table](/hash-table/), its first uses for [duplicate removal](/dedup/) and [counting](/frequency-counter/), the [load factor](/load-factor/), [rehashing](/rehashing/) into a larger table, and [hash codes for records](/hash-code-for-user-defined-types/).
4. **Separate chaining.** A list in each slot, and the [exact analysis](/chaining-analysis/) of its searches.
5. **Open addressing.** Keys in the array itself: [probe sequences](/probe-sequence/), [tombstones](/lazy-deletion/), [linear](/linear-probing/), [quadratic](/quadratic-probing/) and [double hashing](/double-hashing/), and the [uniform hashing assumption](/uniform-hashing-assumption/) that measures them.
6. **Probing in depth.** The [analysis of linear probing](/linear-probing-analysis/), [Yao's lower bound](/yao-open-addressing-lower-bound/), and three modern layouts: [Robin Hood hashing](/robin-hood-hashing/), [hopscotch hashing](/hopscotch-hashing/) and the [Swiss table](/swiss-table/).
7. **Random hash functions.** [Universal hashing](/universal-hashing/), the [attack](/algorithmic-complexity-attack/) it defends against, and the stronger [$k$-wise independent](/k-wise-independent-hashing/) and [tabulation](/tabulation-hashing/) families.
8. **Worst-case lookups and static sets.** [Cuckoo hashing](/cuckoo-hashing/), the [static dictionary problem](/static-dictionary-problem/), [FKS perfect hashing](/fks-perfect-hashing/), [minimal perfect hashing](/minimal-perfect-hashing/), [CHD](/chd-hashing/) and [dynamic perfect hashing](/dynamic-perfect-hashing/).
9. **Tables on disk, and shared terms.** [Extendible](/extendible-hashing/) and [linear hashing](/linear-hashing/), which grow one bucket at a time, and [hash-consing](/hash-consing/).
