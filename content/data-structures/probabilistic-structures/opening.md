A database keeps its rows in files on disk, and reading a file to learn that a key is not there wastes a disk access. If it keeps a small summary of each file in memory that answers "certainly not here" or "maybe here", it reads only the files that may hold the key. Burton Bloom had the same problem in 1970 with a hyphenation program: most words follow simple rules, and only a few need a slow look-up in a dictionary on disk. A summary that is allowed to say "maybe" for a few words that are not in the dictionary can be far smaller than the dictionary itself. This is the trade the chapter studies: an exact answer is given up for space, and the error is one-sided and controlled.

The first half of the chapter is about [approximate membership](/approximate-membership/). A filter for a set $S$ of $n$ keys never says "no" for a key of $S$, and says "yes" for a key outside $S$ with probability at most $\varepsilon$, the [false positive rate](/false-positive-rate/). Storing the keys exactly takes at least $\log_2$ of the number of possible sets, which grows with the size of the universe. A filter needs only $n \log_2(1/\varepsilon)$ bits, whatever the size of the keys: about 10 bits per key for a rate of 1 in 1000, even if each key is a long URL. The [Bloom filter](/bloom-filter/), an array of bits and $k$ hash functions, comes within a factor of $1.44$ of this bound. Later filters close most of the gap, add deletion, or grow with the set.

The second half counts. In a stream of items too long to store, a sketch of a few thousand counters estimates how often each item occurred, with an error of at most $\varepsilon$ times the length of the stream, and another sketch of a few hundred bytes estimates how many distinct items there were. The tools are the same: hash functions that spread the items, and a bound on how much the collisions can add.

## What the chapter covers

The chapter is in five groups, read in order.

1. **Approximate membership.** The [problem](/approximate-membership/), the [false positive rate](/false-positive-rate/) and how to compute it exactly, and the [lower bound](/bloom-filter-lower-bound/) of $n \log_2(1/\varepsilon)$ bits.
2. **The Bloom filter and its variants.** The [Bloom filter](/bloom-filter/) and its [best number of hash functions](/bloom-filter-optimal-hash-count/), and the variants that add deletion with [counters](/counting-bloom-filter/), growth by a series of filters in the [scalable Bloom filter](/scalable-bloom-filter/), decay for streams in the [stable Bloom filter](/stable-bloom-filter/), and a classifier in front in the [learned Bloom filter](/learned-bloom-filter/).
3. **Filters that store fingerprints.** The [cuckoo filter](/cuckoo-filter/) and the [quotient filter](/quotient-filter/), which keep a short fingerprint of each key in a compact hash table and support deletion.
4. **Static filters from linear equations.** The [Bloomier filter](/bloomier-filter/), the [xor filter](/xor-filter/), the [binary fuse filter](/binary-fuse-filter/) and the [ribbon filter](/ribbon-filter/), which solve a system of equations over bits to store one fingerprint per key in close to the minimum space.
5. **Counting in a stream.** The [frequency estimation problem](/frequency-estimation/), the [error bound of the count-min sketch](/count-min-error-bound/), the [spectral Bloom filter](/spectral-bloom-filter/) and the [Flajolet–Martin sketch](/flajolet-martin-sketch/) for distinct items.
