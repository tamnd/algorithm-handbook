Take six states S, A, B, C, D and G, with directed edges S→A of cost 1, S→G of cost 12, A→B of cost 4, A→C of cost 1, B→D of cost 3, C→D of cost 1, C→G of cost 2 and D→G of cost 3. Three searches start at S and look for G. Breadth-first search returns the path S-G, which has one action and costs 12. Depth-first search, trying the first child first, returns S-A-B-D-G, which costs 11. Uniform-cost search returns S-A-C-G, which costs 4, the cheapest. The graph and the successor function are the same in all three; only the order in which the search takes the next state differs. That order is the [search strategy](/search-strategy/), and this chapter is about how to choose it.

Every search here keeps a [frontier](/search-frontier/) of paths that it has generated but not yet expanded. A first-in first-out [queue](/queue/) gives breadth-first search, a [stack](/stack/) gives depth-first search, and a [priority queue](/priority-queue/) on a cost or a score gives the cost-ordered family. Each choice trades three things: whether the search is sure to find a goal, whether the goal it finds is the cheapest, and how much memory the frontier needs. Breadth-first search finds the shallowest goal but holds a whole level of the tree; depth-first search holds one path but can run forever down an infinite branch. Most of the chapter is about getting the good parts of both.

## What the chapter covers

The chapter is in six groups, read in order.

1. **The frame.** A [search strategy](/search-strategy/) fixes the order of exploration. The [search tree](/search-tree/) unfolds every path from the start, so one state can appear in many nodes, and the tree can be infinite when the space is finite. The [search frontier](/search-frontier/) is the boundary between the explored part of the tree and the rest. [Completeness and optimality](/completeness-and-optimality-of-search/) define what a strategy promises, and show that no strategy can promise to detect failure on every problem.
2. **Repeated states.** [Graph search versus tree search](/graph-search-vs-tree-search/) weighs a [hash table](/hash-table/) of reached states against the time spent on repeated ones, and shows when a state must be reopened because a cheaper path to it turns up late.
3. **Searching by depth.** [Depth-limited search](/depth-limited-search/) stops at a fixed depth and says whether it gave up because of the limit or because the space ran out. [Iterative deepening](/iterative-deepening-search/) raises the limit one step at a time; on a tree of branching factor $b$ it does at most $b/(b-1)$ times the work of one search to the goal depth. [Iterative broadening](/iterative-broadening/) limits the number of children instead of the depth.
4. **Searching by cost.** [Best-first search](/best-first-search/) expands the frontier node with the least value of an evaluation function $f$. [Uniform-cost search](/uniform-cost-search/) is the case $f = g$, the cost of the path so far; it is [Dijkstra's algorithm](/dijkstra/) run on a graph that is generated as it goes, and it tests for the goal when a node is taken from the frontier, not when it is made.
5. **Searching from both ends.** [Bidirectional search](/bidirectional-search/) runs one search forward from the start and one backward from the goal; two searches of depth $d/2$ cost about $2b^{d/2}$ instead of $b^d$.
6. **Beyond systematic search.** A [local search problem](/local-search-problem/) asks only for a state that no neighbor improves, which is easy to state and can still be hard to reach. [Simulation](/simulation-technique/) runs a process step by step and skips whole cycles once a state repeats.

## A first reading

Read the four entries of the frame in order, then [graph search versus tree search](/graph-search-vs-tree-search/). Next read [depth-limited search](/depth-limited-search/) and [iterative deepening](/iterative-deepening-search/), and work their traces by hand, including the difference between *cutoff* and *failure*. Then read [best-first search](/best-first-search/) and [uniform-cost search](/uniform-cost-search/), and [bidirectional search](/bidirectional-search/). That is ten entries. [Simulation](/simulation-technique/) is short and introductory and can be read at any point.

[Iterative broadening](/iterative-broadening/) is a research entry, and the [local search problem](/local-search-problem/) leads into complexity theory; both can wait for a second reading.
