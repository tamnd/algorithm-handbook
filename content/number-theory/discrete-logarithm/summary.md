## What to remember

- The answer $x = \log_g h$ is defined modulo the order $n$ of $g$, and exists exactly when $h$ lies in the subgroup generated by $g$. Computing $g^x$ takes $O(\log n)$ group operations; no method is known that inverts it in time polynomial in $\log n$ in the groups used for cryptography.
- [Baby-step giant-step](/baby-step-giant-step/) writes $x = im + j$ with $m = \lceil \sqrt n \rceil$, stores the $g^j$ and walks $h g^{-im}$. It is deterministic, with $O(\sqrt n)$ operations and $O(\sqrt n)$ memory.
- [Pohlig-Hellman](/pohlig-hellman/) reduces a logarithm in a group of order $n = \prod l^e$ to logarithms in the subgroups of prime order $l$, digit by digit, and joins them by the Chinese remainder theorem. The cost is set by the largest prime $l$, so a secure group has a large prime order subgroup.
- [Pollard's rho](/pollard-rho-discrete-logarithm/) walks through elements $g^a h^b$ until a collision, which gives a linear congruence for $x$; it takes about $\sqrt{\pi n / 2}$ steps and $O(1)$ memory. With [distinguished points](/distinguished-points/) the walks run on many machines with linear speedup. The [kangaroo method](/pollard-kangaroo/) does the same for $x$ in an interval of width $w$ in about $2\sqrt w$ steps.
- In the [generic group model](/generic-group-model/), any algorithm that succeeds with constant probability in a group of prime order $q$ needs $\Omega(\sqrt q)$ operations. The square root methods are optimal among generic algorithms, and on a well chosen elliptic curve nothing better is known.
- [Index calculus](/index-calculus/) works with the representation: find exponents $k$ with $g^k$ smooth over a factor base, solve the linear system modulo $n$ for the logarithms of the base, then write $h g^k$ over the base. In a prime field this costs $L_p[1/2, c]$; the number field sieve lowers it to $L_p[1/3, (64/9)^{1/3}]$.
- In fields of small characteristic, Coppersmith's algorithm and the function field sieve reached $L(1/3)$ with the smaller constant $(32/9)^{1/3}$, and since 2013 heuristic quasi-polynomial algorithms make such fields unusable for cryptography.
- A pairing maps the logarithm on a curve with embedding degree $k$ to a logarithm in $\mathbb{F}_{p^k}$ by the [MOV reduction](/menezes-okamoto-vanstone-reduction/). Supersingular curves have $k \le 6$, while a random curve has a huge $k$.

## The methods side by side

| Method | Cost | Memory | Group |
|---|---|---|---|
| [Baby-step giant-step](/baby-step-giant-step/) | $O(\sqrt n)$, deterministic | $O(\sqrt n)$ | any |
| [Pohlig-Hellman](/pohlig-hellman/) | $O(\sum e_i (\log n + \sqrt{l_i}))$ | $O(\sqrt{l})$ | any, order $n = \prod l_i^{e_i}$ known |
| [Pollard's rho](/pollard-rho-discrete-logarithm/) | about $\sqrt{\pi n / 2}$, heuristic | $O(1)$ | any |
| [Parallel collision search](/parallel-collision-search/) | $O(\sqrt n / N + 1/\theta)$ per machine | distinguished points only | any |
| [Kangaroo](/pollard-kangaroo/) | about $2\sqrt w$, heuristic | $O(1)$ | any, $x$ in an interval of width $w$ |
| [Index calculus](/index-calculus/) | $L_p[1/2, 2]$ | factor base and matrix | prime fields |
| [Number field sieve](/number-field-sieve-discrete-logarithm/) | $L_p[1/3, (64/9)^{1/3}]$ | factor base and matrix | prime fields |
| [Function field sieve](/function-field-sieve/) | $L_q[1/3, (32/9)^{1/3}]$ | factor base and matrix | small characteristic |
| [Quasi-polynomial](/quasi-polynomial-discrete-logarithm/) | $\exp(O((\ln \ln q)^2))$ | factor base and matrix | small characteristic |
| [MOV](/menezes-okamoto-vanstone-reduction/) | one pairing, then a field logarithm in $\mathbb{F}_{p^k}$ | as in the field | curves of small embedding degree $k$ |

: Discrete logarithm algorithms. $n$ is the order of $g$, $l$ its largest prime factor, $N$ the number of machines and $\theta$ the fraction of distinguished points. $L_q[\alpha, c] = \exp\big((c + o(1)) (\ln q)^\alpha (\ln \ln q)^{1 - \alpha}\big)$. All costs except the last count group or field operations.

## Choosing a method

In a small group, or one of unknown structure, use baby-step giant-step when $\sqrt n$ elements fit in memory and Pollard's rho when they do not. If the order $n$ is known and has small factors, always run Pohlig-Hellman first, with one of these methods for each prime. If $x$ is known to be small, use the kangaroo method or baby-step giant-step on the interval; their cost depends on the width, not on $n$.

In a prime field of cryptographic size, index calculus in the form of the number field sieve is the only method that matters, and a large precomputation can be reused for many logarithms in the same field. In fields of small characteristic, use the function field sieve or the quasi-polynomial methods. On an elliptic curve, check the embedding degree and the field of definition first; if the curve is ordinary, defined over a prime field and of prime order, parallel rho is the best known attack.
