A vertex cover of a graph is a set of vertices that touches every edge. Finding a smallest one is NP-hard, so no polynomial-time algorithm is expected unless $\mathsf{P} = \mathsf{NP}$, and that question is open. In many inputs, though, the cover sought is small. For a graph with $n = 1000$ vertices and a cover of size $k = 10$, trying every set of ten vertices means $\binom{1000}{10} \approx 2.6 \times 10^{23}$ candidates. Branching on the two ends of an uncovered edge gives a search tree with at most $2^{10} = 1024$ leaves, and each node costs time linear in the size of the graph. The exponential part of the cost has moved from $n$ to $k$.

Parameterized complexity is the study of that move. A problem with a [parameter](/parameter/) $k$ is [fixed-parameter tractable](/fixed-parameter-tractable/) (FPT) if it can be solved in time $f(k) \cdot n^{c}$ for a computable function $f$ and a constant $c$. Vertex cover is FPT. Clique, with the size of the clique as the parameter, seems not to be: the best algorithms take time $n^{\Theta(k)}$. The theory explains this with $\mathsf{W}[1]$-hardness, which plays the part that NP-hardness plays for polynomial time. A $\mathsf{W}[1]$-hard problem has no FPT algorithm unless $\mathsf{FPT} = \mathsf{W}[1]$, and that equality is open.

The same view gives a theory of preprocessing. A [kernel](/kernel/) is a polynomial-time reduction that shrinks an instance to an equivalent one whose size depends on $k$ alone. For vertex cover, three simple rules leave at most $k^2$ edges, and a linear program leaves at most $2k$ vertices. A decidable problem has a kernel exactly when it is FPT, and the theory of kernel lower bounds shows, unless $\mathsf{NP} \subseteq \mathsf{coNP/poly}$, that some FPT problems have no kernel of polynomial size. Treewidth, a parameter of graph structure, gives the third main thread: on graphs of bounded treewidth, every property expressible in monadic second-order logic is decidable in linear time.
